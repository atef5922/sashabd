# Sashabd Technical SEO Audit

Audit date: 2026-08-01  
Canonical property: `https://sashabd.com`  
Safety branch: `seo/technical-seo-audit-2026-08-01`

## Executive summary

The project is a Next.js 16.1.6 App Router application rendered as a static export and deployed to Apache/LiteSpeed on cPanel. It is a hybrid of static pages and build-time generated dynamic catalog/blog pages (SSG); there is no runtime CMS, database, middleware, i18n, reverse proxy configuration, or application server in this repository. Apache rules in `public/.htaccess` provide production redirects, clean URLs, the custom 404 response, and cache/security headers. Cloudflare may sit in front of the origin, but its rules are external to this repository.

The intended canonical policy is confirmed as HTTPS, non-www, lowercase page paths, and trailing slashes. File URLs such as `/robots.txt` and `/sitemap.xml` do not receive a trailing slash. Canonical pages return 200 directly; alternate protocols/hosts and legacy routes use permanent redirects.

The deployed site had 11 audit findings. The rebuilt local production export has zero critical findings across 173 sitemap URLs, 173 unique internal page targets, eight representative legacy redirects, a direct custom 404, and mobile/desktop HTML parity checks.

## Root causes

1. The live Apache configuration sent legacy P4 and P5 indoor URLs to nonexistent P1.77 and P1.35 URLs, producing redirect-to-404 failures.
2. The deployed ordering/configuration normalized a slashless turnstile legacy route before migrating its slug, causing two redirects.
3. Two homepage components linked to `/products/` and `/services/` instead of their canonical destinations. Many other source links omitted the project-wide trailing slash.
4. Canonical URL formatting was partially centralized but did not safely normalize query strings, fragments, duplicate slashes, `index.html`, host/protocol, or path case.
5. Sitemap `lastmod` values were generated from the current clock on every build rather than a stable content-change date.
6. The homepage rendered two H1 elements (one in each responsive branch), and three indoor product pages reused descriptions from sibling models.
7. The alternative `_redirects` file disagreed with Apache for the digital-display migration and could create an extra hop on platforms that consume that file.

## Architecture and deployment findings

- Framework: Next.js 16.1.6, React 19.2.3, TypeScript 5.
- Router: App Router (`app/`).
- Rendering: static export (`output: "export"`), with static routes and SSG dynamic routes generated by `generateStaticParams`.
- Canonical route policy: `trailingSlash: true`, unoptimized static images, no locale prefix.
- Hosting: documented cPanel/Apache or LiteSpeed static hosting; `public/.htaccess` is copied to `out/.htaccess`.
- CDN: Cloudflare is documented, but zone redirect/cache settings are outside the repository.
- Redirects: Apache `mod_rewrite` is authoritative on the documented deployment; `public/_redirects` is an alternate-platform compatibility file.
- Sitemap/robots: native Next.js metadata routes (`app/sitemap.ts`, `app/robots.ts`), force-static.
- Metadata: Next.js Metadata API with shared helpers in `lib/seo.ts`; JSON-LD is server-rendered.
- Data routes: TypeScript catalogs and blog data in the repository; no CMS/database calls.
- CI: no repository CI workflow was found. New Node tests and crawler commands are available for CI integration.

## Confirmed canonical URL policy

- Origin: `https://sashabd.com`
- Host aliases: `www.sashabd.com` permanently redirects to non-www.
- HTTP: permanently redirects directly to HTTPS.
- Page paths: lowercase and trailing-slash terminated.
- File paths: retain their extension without a trailing slash.
- Queries/fragments: excluded from canonical URLs. The existing single `?m=` cleanup remains permanent; search results stay outside the sitemap and are `noindex,follow`.
- Internal links, Open Graph URLs, breadcrumbs, JSON-LD, sitemap URLs, and canonical tags use the same policy.

## Intentional redirects retained

- HTTP and/or www normalization to `https://sashabd.com`.
- Slashless page URLs to their trailing-slash canonical form.
- `/control-systems/...` product families to the shorter top-level PA, podium, panel, and turnstile routes.
- `/products/...`, `/indoor-led/...`, `/rental-display/...`, and legacy LED category aliases to `/led-display/...` canonical routes.
- Historical services, blog, price-guide, rent-guide, video-wall, and `index.html` aliases to their closest equivalent content.
- The isolated legacy `?m=` query cleanup.

Redirect sources are intentionally not indexable pages. Google Search Console may continue to report these source URLs under “Page with redirect”; that is expected and not a reason to remove valid migrations.

## Accidental redirect problems removed

- P4 and P5 redirect-to-404 destinations.
- Two-hop slash normalization before the turnstile legacy migration (repository configuration now matches both slash forms directly).
- Internal `/products/` and `/services/` links.
- Slashless internal page links across navigation, CTA, catalog, blog, legal, and product components.
- Alternate-platform `digital-led-display` redirect through another redirecting route.
- Greedy Apache slug captures that could consume a trailing slash and create malformed destinations.

## Deployment instructions

1. On the audited branch, run `npm.cmd install`, `npm.cmd run lint`, `npm.cmd run typecheck`, `npm.cmd test`, and `npm.cmd run build`.
2. Confirm `out/index.html`, `out/404.html`, `out/robots.txt`, `out/sitemap.xml`, and `out/.htaccess` exist.
3. Back up the current cPanel `public_html` directory.
4. Remove stale route folders and the old `_next` directory only inside the confirmed `public_html` target, then upload the contents of `out/` to `public_html/`. Do not upload the `out` directory as an extra nesting level.
5. Ensure hidden files are visible and verify `public_html/.htaccess` is the newly built file.
6. If Cloudflare is enabled, use Full (strict) TLS and purge only the affected HTML/redirect cache (or perform one controlled full purge immediately after this deployment).
7. Run the verification commands below before Search Console validation.

Rankings cannot be guaranteed. The changes preserve existing public URL equity using direct permanent redirects and align internal discovery signals with canonical destinations.
